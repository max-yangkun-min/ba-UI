# 门户资源交接说明

智能体、知识库、技能、工具、插件的门户目录和详情，交给大系统写进自己的前端。这些页面是 React 组件，自己请求接口再画出列表和详情。接入之后跑在大系统自己的页面里，使用大系统自己的登录和路由。

源码仍保留当时嵌在 `5174` 里的外壳协议。接入时按下一节替换。替换完成后，这些页面不再放进 iframe，也不再使用 `embed_parent` 和 `blade-embed-*` 消息。

大系统接手后，这些页面不再由我们维护。对话和应用开发仍留在我们这边。

本文按交接时的源码写页面、接口和要改的位置，没有另编路径。

## 挂上这些页面

组件在 `blade-product/embed-app/src/pages/`。路由使用 `react-router-dom`。下面的路径是原来的地址，大系统可以改成自己的路径，组件和 `kind` 保持对应。

| 原来的路径 | 页面组件 | 内容 |
| --- | --- | --- |
| `/resources/skills` | `ResourceCatalogPage`（`kind="skills"`） | 技能目录 |
| `/resources/knowledge` | `ResourceCatalogPage`（`kind="knowledge"`） | 知识库目录 |
| `/resources/agents` | `MockAgentCatalog` | 智能体目录 |
| `/resources/tools` | `ResourceCatalogPage`（`kind="tools"`） | 工具目录 |
| `/resources/plugins` | `ResourceCatalogPage`（`kind="plugins"`） | 插件目录 |
| `/resources/:kind/*` | `ResourceDetailPage` | 上面五类的详情。`kind` 为 `skills`、`knowledge`、`agents`、`tools`、`plugins` |

`/resources/prompts` 仍是我们的提示词工程，不在本次交接范围。它转到 `/console/app-dev/prompts`。

目录页点卡片进入详情，地址由 `resourceDetailPath` 生成。大系统如果改了路由前缀，同时改这个函数和 `resource-nav.ts` 里的 `to`。

## 接入时改这几处

### 登录票

安装、卸载、目录和详情都使用当前登录用户的 `access_token`。请求头写成：

`Authorization: Bearer <access_token>`

票只放请求头。地址、query、hash 里不要带票。

源码现在等父页面发来：

```json
{ "type": "blade-embed-token", "token": "<access_token>" }
```

收到后写入 `sessionStorage` 键 `blade-portal-user-ticket`，页面经 `portalInstallToken()` 读取。接入时让 `portalInstallToken()` 返回大系统当前用户的票，或把 `ResourceDetailPage` 里读取这个函数的地方改成大系统自己的会话。

`portal-session.ts` 里向父页面发送 `blade-embed-ready`、等待回票、以及 `public-service/src/lib/embed-grant.ts` 里给 iframe 回票，这两段是外壳协议，接入后不再使用。

### 未登录

安装、卸载、立即体验发现没有用户票时，进入大系统自己的登录页。

源码在 `ResourceDetailPage` 的 `refuseInstall`、`cloneToConsole`、`uninstallFromAccount`、`openExperience` 里调用 `redirectToPortalLogin()`。把这次跳转改成大系统登录页。`src/data/portal-login.ts` 和 `public/portal-login.js` 是给 iframe 顶层窗口准备的，接入后不用加载。`portal-login.js` 里的默认值保持空字符串，不要写成某一台机器的地址。

没有用户票时不要发出安装或卸载请求。

### 立即体验，以及安装成功后打开对话

技能、知识库、插件打开大系统自己的对话页，带上：

| 字段 | 含义 |
| --- | --- |
| `target` | `skills`、`knowledge` 或 `plugins` |
| `id` | 资源编号 |
| `name` | 资源名称 |

智能体打开对话时只带 `target` 为 `agents`。

源码在 `openAccountChat` 和 `openExperience` 里向父页面发送：

```json
{ "type": "blade-embed-open-chat", "service": "portal", "target": "skills", "id": "<编号>", "name": "<名称>" }
```

接入时改成大系统的路由跳转，参数仍用上面的字段。对话页由大系统自己打开。

工具没有立即体验，也没有安装。详情上只有「测试连接」，请求见下一节。

### 页面高度

`embed-resize.ts` 向父页面发送 `blade-embed-resize`，只为了把 iframe 拉高。页面写进大系统自己的布局后，不再发送这条消息，这个文件不用接入。

### 目录用谁的票

用户已经登录时，列表、详情、截图、已添加、已发布，以及工具测试连接，都带这张用户票，请求头是 `Authorization: Bearer <用户票>`。

源码在没有用户票时给这些读取加上 `X-Blade-Portal-Catalog: 1`，并去掉 `Authorization`。开发代理 `portal-catalog-auth.ts` 看见这个头之后，用服务端访问票去读上游。这是我们单独跑嵌入页时的做法。大系统接入后，这些读取直接带当前用户的票。`portal-catalog-auth.ts` 不放进大系统前端，其中的账号密码也不要打进浏览器包。

这些读取对应：

- `GET /api-ba/api/skill-store/catalog`
- `GET /api-ba/api/registry/kb?scope=market`，以及 `GET /api-ba/api/registry/kb/<id>`
- `GET /api-ba/api/market-publish/listings`
- `GET /api-ba/api/published-apps`，以及 `GET /api-ba/api/published-apps/<id>`
- `GET /api-bh/api/resources?type=tool`，以及 `GET /api-bh/api/resources/<id>`
- `GET /api-bh/api/plugins`，以及 `GET /api-bh/api/plugins/<名称>`
- `GET /api-bh/api/skills/<org>/<name>`
- `GET /api-bos/api/v1/market/listings`，单条，以及截图
- `GET /api-bos/api/v1/market/installed`
- `GET /api/catalog-counts`
- `POST /api-bh/api/resources/test`

知识库列表必须带 `scope=market`。缺省的 `default` 会带出访问账号自己的私有库。

若大系统需要未登录也能浏览目录，在自己的服务端代读这些接口。浏览器里仍然只出现当前用户的票，或者不带票。

## 接口

前端现在请求的是相对路径。三个前缀在我们的开发代理里分别转到：

| 前缀 | 上游 |
| --- | --- |
| `/api-ba` | Blade Agent |
| `/api-bh` | Blade Hub |
| `/api-bos` | Blade OS |

大系统的网关继续按这三个前缀转发，页面里的 `fetch` 可以保持不动。网关路径不同时，改这些文件里的请求地址：`features/resources/catalog.ts`、`detail.ts`、`skill-store.ts`、`account-install.ts`、`agent-market.ts`。

### 安装和卸载

有用户票才调用。请求头带这张票。

| 资源 | 安装 | 卸载 |
| --- | --- | --- |
| 技能 | `POST /api-ba/api/skill-store/install`，正文 `{ "skill": "<org/name>" }`。上游是 Blade `POST /api/skill-store/install` | `DELETE /api-bh/api/me/skills/<org>/<name>/install`。上游是 Hub `DELETE /api/me/skills/<org>/<name>/install`。技能编号是 `org/name` |
| 知识库 | `POST /api-bh/api/kb/<id>/install`。`<id>` 为正整数 | `DELETE /api-bh/api/kb/<id>/install` |
| 插件 | `POST /api-bh/api/plugins/<名称>/install`。编号若以 `builtin-` 或 `mine-` 开头，先去掉这个前缀 | `DELETE /api-bh/api/plugins/<名称>/install` |
| 智能体市场上架 | `POST /api-bos/api/v1/market/listings/<id>/install` | `DELETE /api-bos/api/v1/market/listings/<id>/install`。404 表示当前用户本来就没装 |

工具的测试连接是 `POST /api-bh/api/resources/test`。

安装成功后按上一节打开大系统自己的对话。卸载成功只刷新当前详情上的已安装状态。

## 还要接到大系统自己的组件

门户页引用了下面这些模块。交接包没有再复制一份，因为对话和应用开发仍在使用它们。

| 模块 | 用在哪里 |
| --- | --- |
| `components/Icon` | 目录、详情 |
| `components/Toast` 的 `useToast` | 安装、卸载的结果提示 |
| `components/Dialog` | 详情和智能体页上的确认框 |
| `features/agent/BaEmbed` | 旧的内嵌 Blade 页面 |
| `data/site.ts` 的 `baOrigin`、`hubOrigin` | 判断体验地址是否属于 Blade |
| `data/ba-modules.ts` 的 `HUB_ORIGIN` | `ResourceOriginEmbed` 打开 Hub 上的工具页、插件页 |

`Icon`、`Toast`、`Dialog` 换成大系统现有组件，或从我们仓库的同名文件拷过去。样式在 `styles/resources.css` 和 `styles/agent-portal.css`。类名沿用这两份样式；颜色和字体变量与大系统不一致时，按大系统的样式改。

`ResourceOriginEmbed.tsx` 和详情里的 `BaEmbed` 会再开一个 iframe，打开 Blade 上的对话、知识库、工具或插件页。直接接入时不用这个组件。立即体验改为上一节的本系统对话跳转。`baOrigin`、`hubOrigin`、`HUB_ORIGIN` 只服务于这条旧的内嵌。

## 交接包里有什么

目录：`deliver/portal-handoff/`。

直接接入要用的页面和数据：

- `blade-product/embed-app/src/pages/` 下的目录页、详情页
- `blade-product/embed-app/src/features/resources/` 目录、详情、安装、卸载和分类
- `blade-product/embed-app/src/styles/resources.css`
- `blade-product/embed-app/src/styles/agent-portal.css`
- `blade-product/embed-app/src/data/resource-nav.ts`

当时的外壳协议留在包里，方便对照源码，接入时按上文替换，不要再接到运行入口：

- `src/data/portal-login.ts`、`public/portal-login.js`：未登录时让顶层窗口离开 iframe
- `src/lib/portal-session.ts`：向父页面要票，并把票放进后续请求
- `src/lib/embed-resize.ts`：把内容高度告诉父页面
- `src/lib/page-auth.ts`：当时哪些路径走门户票
- `portal-catalog-auth.ts`：无用户票时在服务端换成访问票
- `src/pages/ResourceOriginEmbed.tsx`：再用 iframe 打开 Blade 页面
- `public-service/src/lib/embed-grant.ts`：测试壳把票转给 iframe
- `public-service/src/data/resource-nav.ts`：测试壳顶栏原来的入口

## 我们这边还留着什么

嵌入页继续提供对话和应用开发：

- `/`、`/chat-workspace`、`/chat-admin`、`/chat-general-admin`
- `/console/app-dev/prompts` 与 `/console/app-dev/prompts/:scope/:id`
- `/console/app-dev/<模块>`：智能体创建、知识库搭建、技能开发、MCP 工具、插件、工作流、数据源

直接打开原来的门户地址时，会落到对话页，不再渲染这份目录或详情。`/resources/prompts` 仍转到提示词工程。
