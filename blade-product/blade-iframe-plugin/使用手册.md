# blade-iframe-plugin 使用手册

> 插件版本：**1.1.7** ｜ 目标：已部署好的 Blade Agent(BA) / Blade Hub(BH)

一句话：不改产品代码、不重建镜像、不重新部署，把已跑起来的 BA/BH 变成
**可被 iframe 嵌入**、**可 URL 直链免登录**，并**隐藏品牌 logo** 的形态。

---

## 1. 它解决什么问题

| 问题 | 本插件的做法 |
|---|---|
| 宿主页与 BA/BH 不同源，iframe 里 Cookie 登录失效 | 向 BA / BH 注入桥接脚本，用 `postMessage` 传 Token，请求自动补 `Authorization: Bearer` |
| 想要一条链接直接进工作台（免登录） | `?token=<JWT>` 直链，脚本给 `/api` 补 Bearer，并把地址栏里的 token 抹掉 |
| 不想在页面上看到厂商 logo | 隐藏品牌 logo 与图标 |
| 不想在左下角看到登录用户名 | 隐藏用户名文本，圆圈位置换成齿轮图标（设置入口保留） |

**只做这些，不动任何配色**。界面颜色完全保持产品自带样式。

> **v1.1.7（当前）**：能力中心 = Blade Hub（`:8010`）。v1.1.7 起 BH 与 BA 同等支持
> `?token=` 直链与 `autologin.html` 免登录入口；去品牌化（隐藏 logo、隐藏用户名、齿轮图标）
> 在 BH 上同样生效。BH 账号按钮没有 `aria-label`，脚本靠「侧栏内最后一个含圆形头像的按钮」
> 定位，只拔掉名字、保留整个按钮。

## 2. 安装

### 前置条件

- 目标机上 BA/BH 容器已在运行（默认容器名 `box-ba` / `box-bh`）
- 目标机有 `docker`、`awk`；建议有 `curl`（`status.sh` 用它探活）
- 插件本体很小（约 40 KB），不占带宽、不写 C 盘

### 标准三步

```bash
# 1) 拷贝到目标机（整个目录，约 40 KB）
scp -r blade-iframe-plugin root@<SERVER>:/opt/

# 2) 安装
ssh root@<SERVER> 'sh /opt/blade-iframe-plugin/install.sh'

# 3) 确认
ssh root@<SERVER> 'sh /opt/blade-iframe-plugin/status.sh'
```

装完让浏览器 **Ctrl+F5 硬刷新** 一次（旧 JS 有缓存）。

### status.sh 期望输出

```
== ba ==
container: box-ba  running=yes
static dir: /app/web/apps/web/dist
bridge file: present
slim-ui file: present
index.html: injected
index.html: url-token injected
index.html: slim-ui injected
HTTP url-token script: 200
HTTP slim-ui script: 200
HTTP bridge script: 200
autologin page: present
HTTP autologin page: 200
```

### 常用参数

```bash
sh install.sh --ba-only                  # 只装 BA
sh install.sh --bh-only                  # 只装 BH
sh install.sh --ba box-ba --bh box-bh    # 自定义容器名
sh install.sh --allow-origin http://10.0.0.8:8080   # 多宿主页时白名单，可重复
sh install.sh --restart                  # 装完重启容器（一般不需要）
```

`install.sh` 是**幂等**的，重复执行无副作用。

## 3. 三种接入方式

### 方式零：一键免登录链接（推荐给客户，客户侧零改动）

```text
http://<SERVER>:8020/autologin.html?token=<BO Access Token>
http://<SERVER>:8020/autologin.html?token=<BO Access Token>&refresh_token=<refresh>

http://<SERVER>:8010/autologin.html?token=<BO Access Token>&next=/skills   # 能力中心
```

打开后自动完成：种会话 Cookie → 抹掉地址栏里的 token → 探活 → 跳进 `/chat`。
**全程不出现登录页。** 客户只要挂一条链接或一个 iframe，不用改任何代码。

原理：BA 的登录态就是 Cookie `blade_token`，而 **Cookie 按主机共享、不分端口**，
所以 `:8020` 与 `:8010` 都认。这一步由 `files/autologin.html` 完成，v1.1.7 起 BA、BH 都部署。

参数：`token`（必填）、`refresh_token`（可选）、`next`（可选；默认 BA=`/chat`、BH=`/`，嵌能力中心建议 `&next=/skills`）。

令牌有效期：本环境 `blade-os` 应用级已调为 **10000 小时（约 416 天）**，
一条链接可长期使用，无需定期更换。浏览器会把 Cookie 的 max-age 截断到
400 天（Chrome 104+ 的上限），所以**会话实际寿命约 400 天**；
`autologin.html` 已按 token 的 `exp` 自动推算并钳制，无需手工干预。

详细说明与安全边界见 `给客户的接入说明-免登录直连.md`。

### 方式一：URL 直链（最轻量，适合临时联调）

```text
http://<SERVER>:8020/chat?token=<BO Access Token>

http://<SERVER>:8010/skills?mode=embed&token=<BO Access Token>   # 能力中心
http://<SERVER>:8010/?token=<BO Access Token>                    # 能力中心首页
```

打开即进工作台。也可以省掉 `/chat`：

```text
http://<SERVER>:8020/?token=<BO Access Token>
```

> **key 必须是 JWT**：`/api/auth/me` 对 `sk-blade-v3-...` 这类 **API Key** 会返回
> `auth_type: "api_key"` 且**不带 `token` 字段**，BA 前端拿不到 JWT，socket.io
> 会握手失败（日志里的 `connect_error: Connection rejected by server`），
> 表现为界面能开但实时对话不通。**直链/免登录请用 BO Access Token（JWT，
> `eyJ...` 开头）**；`sk-blade-` 令牌只适合把 BA 当 API 调用。

行为：

- 脚本在页面最早期读取 `?token=`，给同源 `/api`、`/socket.io` 请求补 `Authorization: Bearer`
- 读完立刻用 `replaceState` 把 token 从地址栏抹掉
- Token 只在内存，**不写 Cookie、不写 localStorage**
- Token 无效（`/api/auth/me` 返回 401）→ 自动停止注入 → 正常跳登录页，**不会死循环**

> v1.1.6 起判据收紧：**只有** `/api/auth/*`、`/api/users/me*` 返回 **401** 才算凭证失效。
> **403 不再被当作 token 失效**——BA 的个别接口（如 `/api/users/me/profile`）本来就会
> 返回 403，旧版据此停注入会导致 `/api/chat-groups` 等接口全部 401，
> 侧边栏显示「我的分组 / 分组加载失败」。

也接受 `?access_token=` 和 `#token=`。

> ⚠️ token 放 URL 里，虽然地址栏会被抹掉，但**网关/代理的访问日志里那份抹不掉**。
> 内网联调、受控入口可用；对外生产建议用方式二。

### 方式二：iframe 嵌入（token 不进 URL、不进日志）

```text
BA 完整工作台   http://<SERVER>:8020/?iframe=1
BH 技能商店（能力中心）  http://<SERVER>:8010/skills?mode=embed
BH 领域智能体   http://<SERVER>:8010/solutions?mode=embed
```

宿主页最小协议（因同源策略，跨域无法直接读 Token，只能靠 `postMessage` 传递）：

```js
// 1) 监听 iframe 的就绪信号
window.addEventListener("message", function (event) {
  if (event.origin !== "http://<SERVER>:8020") return;   // 必须校验来源
  if (event.data && event.data.type === "blade-embed-ready") {
    // 2) 回传 Token
    frame.contentWindow.postMessage(
      { type: "blade-embed-token", token: accessToken },
      "http://<SERVER>:8020",
    );
  }
  if (event.data && event.data.type === "blade-embed-authenticated") {
    console.log("已认证");
  }
});
```

现成的宿主辅助（`host/` 目录）：

| 文件 | 用途 |
|---|---|
| `blade-embed-host.js` | 原生 JS，`BladeEmbedHost.bind(frame, { getToken })` |
| `vue-snippet.vue` | Vue 3 组件片段 |
| `example.html` | 零构建联调页，`?ba=&bh=` 指定地址 |

联调页用法：

```text
http://<HOST>/example.html?ba=http://<SERVER>:8020&bh=http://<SERVER>:8010
```

> BA 嵌完整工作台必须用 `?iframe=1`。`?mode=embed` 是官方简化嵌入页，功能不全。
> BH 反过来，用 `?mode=embed`。

## 4. 从哪拿 Token

Token 必须是 **BO Access Token（JWT）**。
**不要**传 OAuth Client Secret，也不要传带中文的整段报错文本。

### 方式 A：已登录的 BA 页面控制台（最省事，现场联调用）

打开已登录的 BA，F12 控制台执行：

```js
fetch('/api/auth/me').then(r => r.json()).then(d => console.log(d.token))
```

输出的就是当前会话的 JWT。本环境已把 `blade-os` 应用级有效期调为
**10000 小时（约 416 天）**，实测 `exp - iat = 10000h`。

### 方式 B：OAuth 授权码流程（脚本化）

```bash
# 1) 浏览器打开（redirect_uri 必须在该应用的 redirect_uris 白名单里）
#    http://<SERVER>:19000/oauth/authorize?client_id=blade-os
#      &redirect_uri=http%3A%2F%2F<SERVER>%3A8020%2Foauth%2Fcasdoor%2Fcallback
#      &response_type=code&scope=openid+profile+email&state=x

# 2) 登录后从地址栏复制 code，换 token
curl -sS -X POST http://<SERVER>:19000/oauth/token \
  -d grant_type=authorization_code -d code=<CODE> \
  -d client_id=blade-os -d client_secret=<SECRET> \
  -d redirect_uri=http://<SERVER>:8020/oauth/casdoor/callback
```

返回体里的 `access_token` 就是要的；同时给 `refresh_token` 续期用。

### 方式 C：贵方登录系统签发（生产环境正解）

客户系统登录后拿到的 Token，经鉴权桥接服务换成平台令牌。
详见 `03_blade-service-deployer/docs/外部登录接入-鉴权桥接方案.md`（B2 方案）。

> `blade-os` 这个客户端**只有 authorization_code 模式**，没有 password grant，
> 所以不能用"用户名+密码直接换 token"。

## 5. 首次登录的其他变化

v2610 起 BA 首次登录会弹一份"先让 Blade AI 更懂你"的引导问卷。
脚本化登录时点 **「稍后再说」** 即可跳过，否则会挡在工作台前面。

## 5.1 调整令牌有效期（可选）

默认 Access Token 24 小时、Refresh Token 720 小时。要发长期有效的免登录链接，
把有效期调长。**关键点：应用级覆盖优先于全局默认。**

- 全局默认：BO 后台 → OAuth 配置 → 「Token 有效期」，
  字段 `default_token_expiry_hours` / `default_refresh_expiry_hours`
- **应用级覆盖**（实际生效的）：`applications` 表里 `blade-os` 的
  `token_expiry` / `refresh_expiry`。BA / BH / BOS 共用这个 client

界面里应用级那两项是**只读展示，没有编辑入口**，只能调 API：

```bash
# 1) 先拿管理员会话（BO 网页端登录后，控制台取 sk-blade-v3-web-… 令牌）
# 2) 改（注意字段名不带 _hours 后缀）
curl -X PUT http://<SERVER>:19000/api/v1/apps/<APP_ID> \
  -H "Authorization: Bearer <admin session token>" \
  -H "Content-Type: application/json" \
  -d '{"token_expiry": 10000, "refresh_expiry": 10000}'
# 3) 回读确认（该接口对未知字段会返回 200 但静默忽略，必须回读）
curl -s http://<SERVER>:19000/api/v1/apps/<APP_ID> \
  -H "Authorization: Bearer <admin session token>"
```

`<APP_ID>` 取 `GET /api/v1/apps` 里 `client_id = blade-os` 那条的 `id`。

改完新签发的 token 立即生效，**已有 token 不受影响**（仍按签发时的 exp 走）。

## 6. 升级 / 重建后必须重装

插件补丁打在**容器内的前端静态文件**上。因此：

| 操作 | 是否需要重装 |
|---|---|
| `docker restart box-ba` | 不需要（文件还在容器里） |
| `docker compose up` 重建容器 | **需要** |
| 产品版本升级（如 v2608 → v2610） | **需要** |

重装就是再跑一次：

```bash
sh /opt/blade-iframe-plugin/install.sh
```

### 若 index.html 被旧版脚本污染

v1.1.2 及更早的注入脚本在 **v2610 上会把标签插进 HTML 注释里**（v2610 的注释正文含
`<script src>` 字样，旧脚本用宽松匹配定位）。v1.1.3 已修复。

如果曾用旧版装到 v2610，先还原再装：

```bash
docker cp /var/lib/blade-iframe-plugin/backups/ba/index.html.last \
  box-ba:/app/web/apps/web/dist/index.html
docker cp /var/lib/blade-iframe-plugin/backups/bh/index.html.last \
  box-bh:/app/web/dist/index.html
sh /opt/blade-iframe-plugin/install.sh
```

## 7. 卸载 / 回滚

```bash
sh /opt/blade-iframe-plugin/uninstall.sh
```

默认只删除注入的脚本标签和桥接文件，**不动**容器里的原始文件结构。

`--restore-backup` 会用安装前的备份盖回 `index.html`。
**升级过产品之后不要用这个参数**，（旧版 index.html 会引用已不存在的静态资源，导致 404）。

## 8. 排障

| 现象 | 原因 / 处理 |
|---|---|
| 宿主页一直收不到 `blade-embed-ready` | 先 `sh status.sh` 看 `bridge file` 是否 `present`；再看是否容器重建过；v2610 上确认用的是 v1.1.3+ |
| BA 页面能开但仍是登录页 | URL 上没带 token，或 token 无效；`?token=` 只对 `?token=` 生效，不读别的参数名 |
| 直链带 token 却跳登录页 | 该 token 已过期/被吊销；换一个新的 |
| 改了配置但没生效 | 浏览器缓存，Ctrl+F5 硬刷新 |
| 需要多宿主页白名单 | `install.sh --allow-origin <ORIGIN>` 重装 |
| 免登录链接停在提示页 | token 已过期或被吊销；重新签发一条链接 |
| `autologin page: missing` | 容器重建过，重跑 `install.sh` 即可恢复 |
| 能力中心（`:8010`）直链跳登录页 | v1.1.6 及更早的插件不处理 BH；**用 v1.1.7 重装**，BH 前端同样只认会话 Cookie，需注入 `url-token-auth.js` |
| 改 BO 有效期不生效 | 应用级覆盖优先于全局默认；字段名是 `token_expiry`（不带 `_hours`），且该接口返回 200 也可能静默忽略，必须回读确认 |
| 侧边栏「我的分组 / 分组加载失败 / 重试」（用的是 `?token=` 直链） | v1.1.4 及更早版本的缺陷：把 `/api/users/me/profile` 的 **403** 误判为 token 失效并停止注入，导致后续 `/api/chat-groups`、`/api/sessions` 全部 401。**用 v1.1.6 重装**即可 |
| 想确认是不是这个缺陷 | 控制台里 `?token` 直链会打出多个 401，其中夹着一个 `/api/users/me/profile` 的 **403**；把该 token 单独 curl `GET /api/chat-groups` 应返回 **200** |
| 界面能进但实时对话不通（`connect_error: Connection rejected by server`） | token 用的是 **API Key**（`sk-blade-v3-…`）而不是 JWT。`/api/auth/me` 对这种令牌不返回 `token` 字段，socket.io 拿不到 JWT。换成 BO Access Token（`eyJ…`） |
| 新建会话报「用户文件目录尚未就绪…不会降级到本地 UUID 目录」 | **与插件无关**：该用户在 Blade OS 侧漏建号。直链只打 `:8020`、绕开门户，所以不会自愈。判定 `curl 'http://127.0.0.1/api/v1/internal/resolve-user?sub=<sub>'`（404 即漏投），再 POST 一次 `user.created` 补投；完整步骤见 `03_blade-service-deployer/readme-for-dev.md` 的「用户漏投 webhook」一节 |

插件版本与安装状态自检：

```bash
cat /opt/blade-iframe-plugin/VERSION
sh /opt/blade-iframe-plugin/status.sh
```

### 安全边界

- 未带 token、且非嵌入态时，脚本**完全不接管** `fetch`/`XMLHttpRequest`，线上行为零变化。
- Token 只留在 iframe / 页面内存，不写 Cookie 与 localStorage。
- 嵌入态要求父窗口来源校验（`--allow-origin` 可收紧到单一来源）。
- 直链 token 会经 URL 与网关日志，属已知取舍，见第 3 节说明。
